# Personal Narrative：第一人称个人叙事

## 定位与分工

- 处理对象：**第一人称个人叙事**——简历项目经历、个人故事、面试素材、自述、创业经历复盘。素材是用户的口语碎片、聊天原话、经历描述。
- 交付目标：**读者读完记住一个人**。
- 不是"读者带走一个判断工具"（那是 ai-worker），不是"去掉 AI 痕迹"（那是 lieflat）。
- 与 ai-worker 共享信息守恒，方向不同：ai-worker 用"不发明"限制声称强度；本 skill 用"不发明"保证写出来的人是用户本人。

## When to Use

用户要求写简历项目经历 / 个人故事 / 面试叙事 / 自述，且素材是用户的亲身经历原话（聊天碎片、口述、经历描述）。不用于：客观调研报告与证据文章（走 ai-worker）、成稿后的 AI 痕迹清理（走 lieflat）、虚构创作。

## 核心原则：零添加，只保护，只放大

情感与人格**不注入**，只从用户原话中提取与保护。任何为了"更像人写的"而新增的情绪、场景、格言、总起句都是失败。

**每条新增内容必须通过测试句**（借自 hannsxpeter/humanizer Stance mode）：
> 这句话是对用户已有内容的看法/组织，还是对世界的新断言？
> 新断言 = 删除。看法 = 用户没要求，也删除。

用户素材本身就是人话 → **默认几乎不动**。改动是例外，逐条可对号。

## 工作流程

1. **素材提取**：从用户原话中逐项提取四类素材，产出 persona 卡（一页内，写作时对照）。清单由每次任务现场提取；skill 不预设固定词表，单次任务的素材不得固化为 skill 特征。每类的判定信号：
   - **特色词**：用户独有的口语 / 情绪词 / 判断短语。判定信号：换个人不会这么说（自我指涉、口语化、带情绪的词组）。
   - **决策点**：用户做过的选择、放弃、止损及其理由。判定信号：转折词或因果结构（"但是""最后决定""果断""纠结后"）+ 行为与理由成对出现。
   - **情绪痕迹**：用户的自我暴露。判定信号：自我评价、自我贬低、犹豫、尴尬的自陈。
   - **核心命题**：从决策点归纳反复出现的判断模式。判定信号：同一类判断在 ≥2 个独立事件中出现才提为命题；单次出现只是事件，不升格。
   - **语域**：用户对同一话题在不同场景的用词切换规则（如某些词只出现在聊天、不进入正式文本）。
2. **验证出处**：persona 卡的每一项都必须在用户原话里逐词指出出处；指不出出处的 = 模型推断，不得进入正文，只能 flag 待确认（借自 writer-persona backtest 信息隔离思想）。
2. **组织**：时间线 + 决策弧线。碎片归位，不重写。决策点站句子主干位置，原话判断句可加粗保留。
3. **克制检查**：过测试句；检查有没有替用户下结论、加总起句、加格言。
4. **句法自审（交付前必做，不等用户指出）**：按 `references/syntax-quality.md` 执行——逐句读出声音，缺陷归类到四类错误（缺失 / 冗余 / 替换 / 语序）+ 标点问题，逐处修正后再输出。用户指出句法问题 = 本步骤执行失败；质检责任不推给用户。
5. **两步回读 + 验证**：先保真回读（事实、特色词、判断句逐项找回），再句法回读（四类错误过筛；两步结构借自 shuorenhua）。交付时附**特色词保留率清单**——列出用户原话中的特色词，逐词标注"已保留 / 已改动 / 已删除"；改动的必须说明理由，且未经用户确认不得定稿。

## 硬性条款（违反即失败）

### 保护级（最高优先级）
- 用户的特色词、口语、情绪痕迹、判断句 = 最高保护级。
- 语域替换（书面化用户原话）是实质性改动：必须 flag + 用户确认，禁止静默。（同 ai-worker 2026-08-24 补丁）
- 例：把用户的口语原话改写成书面语，即使理由更"得体"或更"专业" = 语域替换，必须确认。

### 句法即人格（语言质量是人格表达的一部分）

句法表达不干净，读者感知到的是"文本质量差"，而不是"这个人说话有毛边"——句法毛糙本身就是人格呈现的破坏因素。区分两种"粗糙"，边界不可混淆：

- **人格性毛边（保留）**：用户的口语词、判断方式、有意的重复强调（同一判断词在不同事件中反复出现是节奏，不是缺陷）。
- **缺陷性毛糙（必改）**：分句逻辑断裂、主语或宾语缺失、动宾不搭配、同句重复同一个词、同段重复同一个数字、因果 / 转折关系没显性化、近距用词不一致。
- **内容单元（逐字保护）**：特色词、判断句、数字、事实、情绪词。换一个字都要 flag。
- 判据：读出声音是否通顺；相邻分句的逻辑关系（因果 / 并列 / 转折）是否清楚；同句 / 同段是否有不必要的重复。
- 禁止借"优化"名义做语域替换或添加新内容。优化后的每个分句必须能逐词映射回用户原话。

### 真实性纪律（借自 coinluu/resume-jd-optimizer-cn 硬规则）
- 不编造：学校 / 公司 / 岗位 / 日期 / 数字 / 人物 / 场景 / 心理活动一律不得新增。
- 三层标记：**已确认**（用户原话或明确答复）/ **待确认**（用户说"忘了""大概"）/ **模型推断**。只有已确认进入正文。
- 数字缺口用保守表述（"约""十余"）或问一个问题，不填洞。
- 用户要求造假 / 夸大 → 拒绝，给真实替代表达。

### 克制护栏（借自 hannsxpeter/humanizer）
- Stance 默认关：只组织用户已有的态度，不添加新态度。
- 低密度默认：用户素材是人话，默认几乎不动；全量重写是最大失败。
- 自我相似度天花板（借自 writer-persona self-similarity ceiling）：不要写得比用户本人更"一致"。用户的口语习惯、判断节奏、有意的重复强调是人格的一部分，不应被"打磨"掉；句法缺陷不属于人格，必须修。

### 反摆锤（同 ai-worker 2026-08-24 补丁）
- 连续方向反转反馈（啰嗦 → 干瘪 → 没人味）时停止全量重写，切 in-place：只改最新反馈点名的位置，未点名句子逐字保留。

## 禁止清单
- 总起句、格言、金句收尾（现场识别，无预设清单；典型形态：把用户的某次行为总结成一句人生道理）
- 替用户下结论、过度解读用户的意图
- 书面化特色词（未经授权）
- 把决策点压缩成纯数字（数字是给扫描的，决策是人格）
- 段落层面套叙事框架（StoryBrand / Hero's Journey 等模板是人格杀手，借自 storytelling-expert 的反面教训）

## 验收清单
- [ ] persona 卡已完成（特色词 / 决策点 / 情绪痕迹 / 核心命题 / 语域）
- [ ] 每个数字都有出处，无新增事实
- [ ] 特色词保留率清单已交付，逐词对号
- [ ] 每条改动可指出对应的素材来源，无凭空新增
- [ ] 没有总起句 / 格言 / 替用户下结论
- [ ] 决策点站主干，判断句原话保留
- [ ] 未点名句子逐字保留（in-place 原则）
