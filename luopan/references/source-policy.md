# 信源与垃圾信息过滤

## 目录

1. 来源评级与选择顺序
2. 垃圾信息识别、去重与溯源
3. 原子证据与用户体验证据
4. 论断门控

## 1. 三个维度分别评级

不要把来源压缩成含混的 A/B/C。分别记录：

### Authority

- `primary`：监管文件、统计原表、公司财报/公告、产品说明书、认证/召回记录、专利原文、法院文书、招投标原文。
- `secondary`：券商、咨询机构、学术研究、权威媒体的分析。
- `tertiary`：聚合站、论坛、社交内容、未经核实的数据库条目。

### Evidence type

`filing`、`government`、`product_document`、`certification`、`patent`、`transaction`、`research`、`media`、`user_experience`、`estimate`。

### Verification

- `verified`：原文可访问，摘录直接支持论断。
- `corroborated`：至少两个独立来源一致。
- `unverified`：无法回到原文、单一匿名来源或仅为估算。

券商报告通常是 `secondary + research`，即便质量很高也不是企业经营事实的一手披露。

## 2. 来源选择顺序

1. 找最接近事件或数据生产者的原始材料。
2. 用二手研究理解框架、发现线索和比较口径。
3. 用真实用户、维修、退货、召回等材料补足产品实际表现。
4. 用反方材料寻找边界和失败案例。

深层企业研究不能只依赖官方与机构报告。建立七类来源池：

- 官方/监管：确认边界和硬事实；
- 竞争者：发现不同市场定义和反方框架；
- 客户/渠道：验证购买、使用、续约、库存和价格；
- 供应商：观察订单、产能、认证和依赖；
- 员工/招聘：观察资源配置、执行能力和组织风险；
- 行为/替代数据：寻找领先于财报的变化；
- 传闻/异常：保留潜在重大但未证实信息。

官方信息通常更准确但更晚，并且有披露激励；替代数据通常更早但噪声大。二者不是互相替代，而是分别回答“已经确认什么”和“可能正在变化什么”。

未上市或信息稀缺企业不要按来源篇数追求完整。先按足迹类型建立配额：主体与所有权、产品存在、客户需求、供应链/产能、组织人员、竞争替代、风险异常。详见 `private-sparse-company.md`。

对于只有宣传稿、融资稿和创始人采访的企业，至少找到一条企业外部生成的交易/监管/客户证据后，才可判断经营活动已经发生。

## 3. 垃圾信息识别

出现以下信号时降低权重或剔除：

- 无作者、无日期、无原始链接、无统计口径。
- 标题堆砌“十大、揭秘、暴涨、必看”，正文没有新增证据。
- 多站正文高度相似，实际来自同一篇通稿或 PR 稿。
- 只引用搜索结果摘要、图表截图或“业内人士称”。
- 产品评测带返佣链接，却不披露样机、测试方法和使用周期。
- 用户评论短时间集中爆发、措辞模板化、账号历史异常。
- 只陈列专利数量、研发费用或招聘数量，直接推导技术领先。
- 使用未来年份“年报”、尚未发生的事件或超出报告截止日的数据。
- 百分比没有分母，增长率没有基期，市场份额没有市场定义。

“未来事件”不是天然垃圾：当前日期之后的事件才是未来。研究必须以运行时日期为锚；发现看似超出模型旧知识的上市、许可或财报时，先查监管登记和正式申报，禁止凭记忆判假。

## 4. 去重与溯源

- 按规范化 URL、标题、关键句和引用对象去重。
- 转载必须追到最早可识别来源；多个转载只算一个证据簇。
- 同一家机构的不同文章若使用同一底层数据，只算一个数据来源。
- 搜索摘要只记录为 `discovery_only`，不得进入核心论断证据。
- 将处理结果写入 `discarded_sources[]`。纯重复或无新增证据可 `duplicate/discard`；潜在影响重大但无法核实的材料必须 `downgrade_to_intelligence` 并链接对应情报项。

## 4.1 原子证据

- `sources[]` 描述来源整体；`evidence[]` 描述来源内可定位的一条证据，两者不得混用。
- 每条原子证据保留原文摘录、非空页码/章节/时间戳定位、立场、证据类型、观察日期和质量缺陷；原子摘录必须能在对应来源摘录中逐字找到。
- 复合论断拆成可分别验证的组成部分；任何一部分证据不足都要降低整体置信度或拆开报告。
- 同一来源的管理层说法与可观察经营数字应拆成两条 evidence，因为前者是叙事，后者才可能是事实。

## 5. 用户体验证据

用户体验用于回答“产品实际解决了什么、哪里失败”，不能直接回答市场份额或故障发生率。

优先级从高到低：

1. 召回、监管投诉、法院/仲裁、公开维修与质量通报。
2. 有型号、版本、购买时间、长期使用过程的可验证评论。
3. 专业测试中披露设备、方法、对照组和原始结果的评测。
4. 大规模平台评论的聚类信号。
5. 单条论坛或社交帖子。

执行规则：

- 按 SKU/型号/版本分开，避免把旧型号问题污染新品判断。
- 区分开箱体验、30 天体验、长期耐久和售后体验。
- 将问题归类为性能、可靠性、易用性、兼容性、服务、价格预期。
- 同时采集正面与负面样本，避免只搜“缺点”制造负面偏差。
- 报告样本量、平台、时间窗和偏差；禁止把评论占比写成真实故障率。

## 6. 论断门控

核心论断必须包含：

- 论断文本；
- 事实、推断或预测标签；
- 至少一个证据 ID；
- 适用范围和时间；
- 置信度；
- 主要反证或未知项。

高置信事实没有一手来源时，两个二手来源必须同时满足：发布者不同、规范化 URL 不同、两边都有且 `content_hash` 不同。不同媒体名称转载同一 URL、同一通稿或同一底表仍只算一个来源。

高置信推断/预测若已找到反证，必须保存至少一条 `stance: contradicts` 的原子证据；若没有找到，记录实际搜索范围和未找到的原因，不能把空数组标成 `searched_found`。

没有非空原文摘录的来源只能作为背景阅读，不能承担关键数字，也不能把 Deep 来源视角标成 `covered`。`discovery_only` 即使被包装成原子证据、指标或信号，也不得支撑论断。

未经证实的信息不通过论断门控，但可以进入 `intelligence_items[]`。禁止因不够确定就删除；也禁止把它伪装成核心事实。
