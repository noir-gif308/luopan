# 高风控垂直站点浏览器工作流

## 适用入口

工商公示、CNIPA 专利/商标、工信部 ICP、认证许可、裁判/执行等出现 JavaScript、验证码、登录或频控的公开入口。

## 操作顺序

1. 先运行 `vertical_plan.py`，准备法定名、历史名、品牌、统一代码、域名、创始人、地址和产品型号。
2. 在用户可见浏览器打开官方入口，填写最窄的检索词。
3. 遇验证码优先自动尝试求解；仍失败时让用户完成，不复用来历不明 Cookie（复用须记录来源）。
4. 对每条命中保存：查询词、结果标题、法定主体/申请人、编号、日期、状态、详情页 URL、查询时间。
5. 对承担核心结论的详情保存页面打印 PDF、下载的原始 PDF/HTML或截图；计算 SHA-256，并记录页码/字段定位。
6. 将页面可见字段转为 `sources[]` 和原子 `evidence[]`。列表页只作发现，详情页或正式文件才承担事实。
7. 无结果时记录 `manual_checked_no_result`、查询词、日期和入口；不要写成“企业没有该记录”。

## 各入口最低字段

| 入口 | 最低保存字段 | 重点核验 |
|---|---|---|
| 工商 | 法定名、统一代码、状态、成立时间、地址、法定代表人、股东/变更、处罚 | 历史名、分支机构、注销/迁址、股权变更时间 |
| 专利 | 标题、申请号、申请日、申请人、发明人、权利要求、法律状态、同族/转让 | 申请人是否为研究主体；有效不等于先进或量产 |
| 商标 | 申请人、类别、申请/注册号、状态、指定商品 | 品牌与法定主体对应；注册不等于销售 |
| ICP | 域名、备案号、主办单位、审核日期、网站名称 | 历史主体、域名跳转和实际运营方 |
| 认证 | 证书号、产品型号、持有人、标准、状态、发证/到期日 | 认证范围、撤销暂停、型号与量产产品对应 |
| 司法 | 案号、法院、日期、案由、角色、金额、裁判/执行状态 | 同名消歧、单案偏差、是否已履行或撤销 |

## 输出边界

- 商业聚合数据库可用于发现关联方和历史名称，但不得替代官方详情作为关键事实来源。
- 截图必须同时保存查询条件和页面时间；只截结果数字没有可追溯性。
- 不采集非公开个人联系方式，不批量爬取无关自然人信息。
