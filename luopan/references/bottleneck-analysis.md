# 供应链瓶颈镜头

仅在用户明确要求卡点、瓶颈利润池、供应紧缺或解除风险时读取，并与 `manufacturing.md` 共用供应链事实底座。供应链节点存在不等于它是瓶颈，瓶颈存在也不等于被研究企业能获利。

## 物理拆解

从终端需求向上拆到核心组件、子组件/材料、设备/原料和基础设施。每个 `bottleneck_nodes[]` 必须关联已有 `supply_chain_nodes[]`，并调查：

- `supply_concentration`：供应商数量、份额、地域和可用产能，而非公司宣传的“全球领先”；
- `expansion_lead_time_months`：许可、设备、建设、爬坡和良率达到稳定水平所需时间；
- `substitution_difficulty`：替代路线、性能/成本折损和切换条件；
- `capacity_utilization`：名义产能、有效产能和利用率口径；
- `demand_growth`：终端真实需求、库存和重复下单影响；
- `qualification_lead_time_months`：客户验证、认证、可靠性和量产导入周期；
- `profit_capture`：涨价、毛利率、合同条款、份额和现金流是否证明企业捕获了稀缺利润；
- `relief_conditions`：新增产能、替代技术、需求下降、政策变化或客户自制何时解除瓶颈。

数值缺失写 `null` 并列入 `unknowns[]`，不得用 0 代替。不要采用固定“红灯数量”直接评级；行业周期和量纲不同，先解释机制，再给 `confirmed/likely/weak_signal/not_bottleneck/unknown`。

## 交叉验证

至少尝试三类独立视角：供应商原始披露、客户/下游验证、产能/许可/设备/价格等外部行为证据。高置信 `confirmed` 至少需要两个不同发布者和不同规范化 URL 的独立来源、两条实质不同且明确支持的可定位原子证据，并覆盖四个以上瓶颈维度；所有已填写的集中度、扩产、利用率、需求增速和认证周期数值必须出现在引用摘录中。复制同一摘录并更换证据 ID 不计为多源。

最终必须回答：

1. 卡在哪里，为什么不能快速扩张或替代？
2. 谁实际获得利润，被研究企业的瓶颈业务占比是多少？
3. 瓶颈何时、以什么条件解除？
4. 解除后企业还剩什么护城河？
5. 当前估值是否已经提前计入最乐观供需？
